# حالة ربط واجهة يمنا بالخلفية

**تاريخ المراجعة:** 20 أغسطس 2026  
**النطاق:** واجهات React الحالية وعقود REST وWebSocket تحت `/api/v1`.

## تدفقات موصولة بعقود خلفية فعلية

| المجال | واجهة المستخدم | العقد المستخدم | التحقق المتاح |
|---|---|---|---|
| الوصول | التسجيل وتسجيل الدخول | `POST /auth/register` و`POST /auth/login` | اختبار عقود الواجهة وتدفق وصول تفاعلي |
| المحتوى | التغذية وإنشاء المنشور والملفات العامة | `/posts` و`/users` | اختبار البناء ومراجعة مسارات الواجهة |
| البحث | البحث العام والفلاتر | `GET /search` | اختبار خدمة ومتحكم البحث والتحقق الحي للفلاتر |
| العلاقات | الأصدقاء والطلبات والمتابعات | `/relationships/*` | ربط صفحات الأصدقاء القائمة |
| الحظر | قائمة المحظورين وإلغاء الحظر | `GET` و`DELETE /relationships/block/:userId` | اختبار عقد REST لإلغاء الحظر |
| المجتمعات | القائمة والانضمام والمغادرة | `/communities/*` | ربط صفحات المجتمعات القائمة |
| الرسائل والإشعارات | القوائم والقراءة والتحديث الحي | `/messages/*` و`/notifications/*` وSocket.IO | اختبارات دورة الحياة والتحقق المرئي |
| الدعم | إنشاء طلب ودليل حالة الطلبات | `POST` و`GET /support/tickets` | اختبار عقد REST وحالات التحميل والخطأ والدخول |
| الحساب | قراءة وتحديث الملف الشخصي | `GET` و`PATCH /users/me` | اختبار عقد REST وحالات التحميل والخطأ والدخول |
| الوسائط والألبومات | عرض المكتبة والفلاتر والألبومات ورفع وحذف وسيط | `GET` و`POST` و`DELETE /media/*` | اختبار عقد FormData وفحص TypeScript وحالة الجلسة المرئية |
| الإدارة | الإحصاءات والمستخدمون والبلاغات وتذاكر الدعم وتحديث حالاتها | `GET` و`PATCH /admin/*` | اختبارات عقود REST، واختبار واجهة لحالتي عدم التسجيل و`403`، وفحص هاتفي |

## مبدأ التحقق

يتحقق عميل REST من رمز الوصول من التخزين المؤقت للجلسة ويرسله في ترويسة `Authorization` فقط عند وجوده. صفحات الدعم، الحساب، والحظر لا تطلب بيانات محمية عندما لا توجد جلسة؛ بل تعرض دعوة صريحة لتسجيل الدخول. ويعرض كل تدفق موصول حالات **تحميل** و**خطأ** و**إعادة محاولة** أو **حالة فارغة** بحسب النتيجة.

> لا تُخزّن أي عناوين قواعد بيانات أو كلمات مرور أو مفاتيح Redis في الواجهة أو في هذا التوثيق.

## حدود العقود الحالية

تظل شاشات تغيير البريد أو الهاتف، رموز الاسترداد، تعطيل الحساب، وحذف الحساب محتفظة بالتصميم وسير التفاعل المرئي، لكن الخلفية الحالية لا تعرض بعد عقوداً آمنة للتحقق من كلمة المرور، إرسال رمز تحقق، تأكيد وسيلة اتصال، أو تنفيذ تغيير حالة الحساب. ولذلك لا يصح اعتبار تلك الأزرار عمليات حساب مكتملة من طرف إلى طرف إلى أن تضاف العقود والتحقق وسياسة الأمان المناسبة.

ترتبط مكتبة الوسائط الحالية بالقراءة والرفع والحذف والألبومات. أمّا الصفحات والفعاليات والحالات وReels والبث المباشر فتعرض واجهاتها الموجودة، لكن لا تُدّعي هذا السجل أنها مرتبطة بعقود CRUD كاملة، لأن العقود المطلوبة لها ليست ضمن مجموعة REST الحالية أو لم تُوصل بعد في الواجهة.

تجلب لوحات الإدارة البيانات الحية فقط عند وجود جلسة؛ فهي تعرض طلب تسجيل دخول المدير عند غيابها، ورسالة منع عند عودة `403`. تقتصر العقود الإدارية الموصولة على الإحصاءات والمستخدمين والبلاغات وتذاكر الدعم وتحديث الحالات. وتبقى أزرار الأدوار والصلاحيات والصيانة والتقارير في الواجهة موجودة بصرياً، لكن لا تُعامل كعمليات خادمية مكتملة ما لم تضاف لها عقود محمية وسجل تدقيق مناسب.

## ما يلزم قبل إغلاق التغطية الخلفية الشاملة

1. تصميم عقود آمنة لتغيير البريد والهاتف والاسترداد وتعطيل أو حذف الحساب، مع تحقق كلمة المرور ورموز قصيرة العمر وسجل تدقيق.
2. إضافة العقود الخلفية المطلوبة للصفحات والفعاليات والحالات وReels والبث المباشر، ثم ربط الصفحات القائمة بها دون إنشاء شاشات إضافية.
3. تنفيذ اختبار متصفح تكاملي بحساب اختبار معزول لتغطية العمليات المحمية الناجحة، إلى جانب الاختبارات الحالية للعقود والتنقل.
