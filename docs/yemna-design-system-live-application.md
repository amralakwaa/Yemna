# تطبيق نظام تصميم «يمنا» على الواجهة الحية

**الغرض.** يترجم هذا المستند رموز التصميم المعتمدة في لوحة العلاقات ولوحة الرسائل والخصوصية إلى خطة تنفيذ آمنة في الواجهة الحية. لا يغيّر أي عقد REST أو منطق صلاحيات أو مصدر بيانات؛ وتظل القيم المتعلقة بالمستخدمين والعلاقات والرسائل والإشعارات مصدرها الاستجابات الحية فقط.

> **مبدأ التطبيق:** نضيف طبقة رموز فوق التنسيقات القائمة، ثم نعمم المكوّنات تدريجياً عبر المسارات الحية. لا يُعاد تصميم شاشة أو فتح مسار محمي لمجرد تطابقه البصري مع اللوحات المرجعية.

## مصدر الرموز والنطاق

يعتمد التنفيذ قيم الألوان والتباعد والقياسات المعتمدة في [`batch14-relationship-content-and-design-tokens.md`](./batch14-relationship-content-and-design-tokens.md). تستخدم اللوحات المرجعية نفس الهوية البصرية، لكنها لا تغيّر سلوك المنتج ولا تمثل بيانات تشغيلية.

| طبقة النظام | الملف أو الموضع المستهدف | مسؤوليتها | ما لا تلمسه |
|---|---|---|---|
| رموز التصميم العامة | `client/src/index.css` | الخطوط، ألوان السطح والنص، أنصاف الأقطار، وأحجام التحكم | عقود API أو حالة الجلسة |
| تحسين الهاتف RTL | `client/src/mobile-ui-refresh.css` | التباعد، الحقول، الأزرار، الصفوف، والتنقل السفلي عند الهاتف | تخطيط سطح المكتب غير المعني |
| المصادقة | `client/src/auth-mobile-refresh.css` | غلاف الدخول والتسجيل والحقول وحالات الوصول | `api.login` و`api.register` وحفظ الجلسة |
| صفحات العلاقات | مكوّنات العلاقات والمسارات الحية القائمة | صف العلاقة، التبويبات، البحث، الإجراءات السياقية | حالات العلاقة غير المتاحة من الخادم |
| الرسائل والخصوصية | المكوّنات الحية المرتبطة بعقود الرسائل والإعدادات | البحث، الصفوف، المؤلف، التبويبات، مفاتيح الاختيار | فتح ميزات أو إعدادات بلا عقد مخصص |

## ترتيب التنفيذ المقترح

| الأولوية | نطاق التطبيق | المخرجات القابلة للفحص | معيار القبول |
|---:|---|---|---|
| 1 | طبقة الرموز | متغيرات CSS موثقة للأحمر والأسطح والنصوص والتباعد وارتفاع التحكم | لا تغير مرئي غير مقصود خارج النطاق المستهدف |
| 2 | مكوّنات الأساس | صف علاقة، زر أساسي، حقل بحث، تبويبات، قائمة خيارات، شارة | نص واضح، مساحة لمس 44px، وتركيز لوحة مفاتيح ظاهر |
| 3 | العلاقات | الاقتراحات، الطلبات، الأصدقاء، المتابعون، الحظر، والبحث الحي | كل إجراء يبقى متصلاً بعقده الحالي وتعرض الأخطاء بصدق |
| 4 | الرسائل | صندوق الوارد، الصفوف، المحادثة الخاصة، إنشاء محادثة، المعلومات | لا تفتح محادثة أو ترسل رسالة دون العقد الحي المناسب |
| 5 | الخصوصية | المحور، الجمهور والرؤية، الحظر، وإعدادات الرسائل المتاحة | لا يعرض اختيار قابل للتعديل ما لم يكن له مسار حفظ حقيقي |
| 6 | التحقق | اختبارات المسارات، اختبارات الانحدار، ولقطات 390×844 | لا قص أفقي، ولا تراجع في الجلسة أو الصلاحيات |

## مواصفات المكوّنات المشتركة

| المكوّن | واجهة الاستخدام الحية | تفاصيل التنفيذ | حالات المحتوى |
|---|---|---|---|
| `RelationshipRow` | الاقتراحات، الطلبات، القوائم، الحظر | صورة 40px، اسم مرتبط بالملف، وصف ثانوي، زر أو إجراء سياقي | تحميل، فارغ، خطأ، معطّل |
| `PrimaryActionButton` | إضافة، قبول، متابعة، بدء محادثة | أحمر `#C9152A`، نص أبيض، ارتفاع 44px، ضغط مرئي | عادي، جاري الإرسال، معطّل، خطأ |
| `SegmentedTabs` | طلبات الصداقة، المتابعون، الرسائل، الحظر | مؤشر سفلي أحمر مع تسمية وصول واضحة | نشط، غير نشط، مركّز |
| `RtlSearchField` | الأصدقاء، الأشخاص، الرسائل، المحظورون | أيقونة بحث، placeholder عربي قصير، اتجاه RTL | فارغ، به استعلام، مركّز، خطأ |
| `SettingsRow` | الخصوصية ومعلومات المحادثة | عنوان، وصف ثانوي اختياري، قيمة أو سهم سياقي | افتراضي، معطّل، خطر |
| `EmptyState` | القوائم التي لا تعيد بيانات حية | وصف صادق وإجراء واحد متاح فقط | لا يستخدم لإخفاء فشل الطلب |

## قواعد الرسائل والخصوصية

تستعمل الرسائل عنواناً واضحاً للجهة المقابلة وملخصاً قصيراً وآمناً في صندوق الوارد، ولا ينشأ محتوى محادثة افتراضي لإكمال التصميم. في المحادثة الخاصة، يكون حقل الكتابة معطّلاً أو غير ظاهر حين لا يتوفر سياق المحادثة الحي. أما الخصوصية فتفصل بين **صف العرض** و**صف الحفظ**: يمكن عرض إعداد حي موجود، لكن زر التبديل أو الاختيار لا يظهر قابلاً للتغيير ما لم تتوفر عملية حفظ مخصصة وناجحة.

| الحالة | النمط البصري | السلوك المطلوب |
|---|---|---|
| جارٍ التحميل | هياكل صفوف محايدة بلا أسماء أو أعداد | منع التفاعل غير الصالح حتى اكتمال الاستجابة |
| لا توجد نتائج | وصف عربي صادق وإجراء عودة أو مسح بحث | لا تضف مستخدمين أو رسائل مصطنعة |
| فشل التحميل | وصف موجز وزر «إعادة المحاولة» | إعادة الاستدعاء نفسه فقط |
| إجراء جارٍ | نص الزر «جارٍ الحفظ…» أو مؤشر صغير | منع التكرار مع الحفاظ على السياق |
| إجراء حساس | أحمر مع أيقونة أو وصف يوضح النتيجة | تأكيد عند الحاجة واستجابة خطأ حقيقية |

## ضمان RTL والوصول على الهاتف

تعتمد جميع الصفوف `dir="rtl"` على مستوى الشاشة، مع عدم قلب أيقونات المعنى العام مثل البحث أو الإرسال بغير اختبار. يوضع الاسم في بداية التسلسل القرائي العربي، ويكون الإجراء الأساسي في الموضع المتسق بصرياً ضمن الصف. تحافظ الحقول والأزرار والمفاتيح على حد أدنى **44×44 بكسل**، وتظهر حلقة تركيز مرئية، وتُعلن مفاتيح الاختيار بحالتها النصية لا باللون وحده.

## مصفوفة التحقق قبل التوسع

| فحص | المسارات المستهدفة | التحقق |
|---|---|---|
| عقد البيانات | العلاقات والرسائل والخصوصية | لا يظهر إجراء كتابة بلا عملية REST حية |
| اختبار واجهة | الصفوف والأزرار والتبويبات والبحث | التسميات، التعطيل، والاستجابة للوحة المفاتيح |
| لقطة هاتف | 390×844 | لا تجاوز أفقي، ولا قص للعنوان أو الإجراء أو التنقل السفلي |
| جلسة مصادقة | صفحة عامة ومسار محمي | لا تراجع لحالة خروج أو تسريب بيانات |
| تراجع بصري | الهاتف وسطح المكتب | لا يفسد تصميم الشاشة غير الداخلة في الدفعة |

## قرار الاعتماد

تبدأ الدفعة البرمجية التالية بطبقة الرموز ومكوّني `RelationshipRow` و`RtlSearchField`، ثم تطبق على العلاقات الحية. بعد اجتياز اختبارات العقود واللقطات، ينقل النمط نفسه إلى صندوق الوارد والخصوصية **فقط** في المسارات التي تثبت عقودها الحية. يظل أي مسار بلا عقد مخصص محمياً برسالة صادقة بدلاً من واجهة شكلية قابلة للتفاعل.
